Development Environment

This document describes how to set up a development environment for contributing to the langchain-azure repository. It covers the available development container options and how to configure your environment for local development. For information about running tests, see Testing, and for CI/CD workflows, see CI/CD Workflows.

Dev Container Overview
The langchain-azure repository uses Development Containers to provide a consistent, pre-configured development environment that works across different platforms. The dev container includes all necessary dependencies pre-installed, letting you start developing right away without worrying about setting up your local environment.

Ubuntu Jammy as the base OS

Azure CLI for interacting with Azure services
Essential build tools and libraries
VS Code extensions for Python development
Setup Options
There are two primary ways to use the development container:

GitHub Codespaces: Cloud-based development environment (no local setup required)
VS Code Dev Containers: Local container-based development

Setup with GitHub Codespaces
GitHub Codespaces provides a complete, cloud-hosted development environment that can be started directly from the repository without any local setup.

To start a GitHub Codespace:

Navigate to the 
langchain-azure repository
Click the "Code" dropdown menu
Select the "Codespaces" tab
Click "Create codespace on master"
Alternatively, you can use the direct link: 
![Open in GitHub Codespaces
](https://codespaces.new/langchain-ai/langchain-azure)

This will create a cloud-based development environment with all dependencies pre-installed and ready to use.

Setup with VS Code Dev Containers
If you prefer to develop locally, you can use VS Code with the Dev Containers extension:

Prerequisites
Docker Desktop installed and running
Visual Studio Code installed
Dev Containers extension installed in VS Code
Setup Steps
Fork and clone the repository to your local machine
Open VS Code
Press F1 and select "Dev Containers: Open Folder in Container..."
Navigate to the cloned repository folder and select it
Wait for the container to build and start (this may take a few minutes on first run)
Once complete, you'll be working inside the development container
Alternatively, you can use the direct link:Open in Dev Containers

VS Code Configuration
The devcontainer.json file configures VS Code to work optimally with the container:

Sets the container name to "poetry3-poetry-pyenv"
Adds the Azure CLI as a container feature
Installs useful VS Code extensions:
ms-python.python for Python language support
njpwerner.autodocstring for automatic docstring generation

Working with the Development Environment
Once your development container is running, you can use standard poetry commands to manage dependencies and start developing:

Install dependencies:

poetry install
Activate the virtual environment:

poetry shell
Run tests:

poetry run pytest
Add new dependencies:

poetry add <package-name>
The development container comes with Poetry configured to create virtual environments inside the project directory (poetry config virtualenvs.in-project true), making it easier to work with VS Code's Python extension.

Tips and Best Practices
Line Endings
When working with the same repository folder in a container and Windows, you may encounter line ending issues. The .gitattributes file in the repository root is configured to disable line ending conversion to prevent conflicts.

Container Rebuilding
If you need to update the container configuration:

Make changes to the Dockerfile or devcontainer.json
Open the Command Palette (F1) and select "Dev Containers: Rebuild Container"
Performance Considerations
The first time you build the container, it may take several minutes
Subsequent startups will be much faster as Docker caches the built image
Mount operations between the host and container can be slow on some systems, particularly on Windows with WSL2

The development container provides a consistent environment that closely matches what's used in the CI/CD pipelines, helping ensure that code that works in your development environment will also work in the CI/CD process.
